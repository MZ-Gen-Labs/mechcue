# 適用ターゲットと構想モデルMCP

## ターゲット製品

| 製品 | MechCueで検討する項目 | 優先度 |
|---|---|---|
| 立形工作機械・マシニングセンタ | XYZ送り、回転・傾斜、可動部とワークの位置関係 | 重点1 |
| ガントリ・直交搬送装置 | 搬送範囲、軸の親子関係、搬送順序 | 重点2 |
| 組立・圧入・検査装置 | クランプ、昇降、スライドと工程の同期 | 次段階 |
| 包装・充填装置 | 搬送と開閉・押出しのタイミング | 次段階 |
| インデックステーブル装置 | 間欠回転と各工程の同期 | 次段階 |
| パレット・工具交換装置 | 交換手順、移動・旋回・退避 | 次段階 |
| プレス・金型開閉装置 | 上下、型開き、取り出しの順序 | 次段階 |
| 多関節ロボット設備 | 関節と周辺設備の同期 | 将来：逆運動学等が必要 |

工作機械は直線・回転軸と可動部の親子関係を段階的に検証できるため重点1としました。直交搬送装置は同じXYZの仕組みを再利用でき、工作機械へのワーク供給にもつなげられるため重点2です。この優先度はMechCueの現在の機能と開発効率に基づく判断で、市場規模の順位ではありません。

製品構成の参考： [DMG MORIの立形加工機](https://us.dmgmori.com/products/machines/milling/vertical-milling)、[Festoの直交ロボット](https://www.festo.com/us/en/c/products/handling-systems-and-industrial-robots/cartesian-robots-id_pim108)。生成モデルはこれらのメーカー製品の複製ではなく独自の概略構成です。

## 今回追加する機能

| MCPツール | 操作 |
|---|---|
| `solidedge_list_concept_templates` | テンプレートと軸構成を一覧。Solid Edge接続不要 |
| `solidedge_create_concept_machine` | 新規フォルダーにオーダード部品、アセンブリ、軸定義JSONを生成・保存 |
| `solidedge_get_concept_machine` | 軸の種類・親子関係・可動範囲、実際の部品配置を取得 |
| `solidedge_set_concept_pose` | 全軸の位置を指定し、子部品を含めてまとめて移動 |

従来の押し出し・切り抜き・部品配置・基準平面拘束・図面ビュー・PDF出力MCPも使用できます。たとえば生成アセンブリを図面化し、正面・上面・等角図で配置を確認できます。寸法・公差の自動記入は未対応です。

## テンプレート

- `mill3`：Yサドル→Xテーブル→ワーク、独立したZ主軸・工具。
- `mill4`：上記のXテーブル→C回転テーブル→ワーク。
- `mill5`：Xテーブル→A傾斜台→C回転テーブル→ワーク。テーブル側に2回転軸を持つ構成です。
- `gantry`：X→Y→Zの直交搬送と簡略グリッパ、支持部、固定ワーク。

回転軸は親の座標系に対して定義します。今回のAはローカルXまわり、CはローカルZまわりです。軸数が同じでも主軸側・テーブル側の配置で構造が変わるため、添付参考図にある主軸傾斜構成とは異なります。[HaasのC軸説明](https://www.haascnc.com/service/online-operator-s-manuals/mill-operator-s-manual/mill-spindle-c-axis-drive-.html)も参照してください。

## 利用例

Solid Edgeを起動し、MCPトレイを「作成・編集も許可」に設定します。生成先の親フォルダーを用意してください。指定する生成先自体は存在しない必要があります。

```json
{
  "type": "mill5",
  "outputDirectory": "C:\\CAD\\ConceptMill5",
  "xTravelMm": 500,
  "yTravelMm": 300,
  "zTravelMm": 300
}
```

`solidedge_create_concept_machine`に上記を渡します。必要なら`partTemplate`と`assemblyTemplate`に使用環境の空のテンプレートの絶対パスを指定します。省略時はSolid Edgeの既定テンプレートを使用します。

結果の`fullName`と`manifestPath`を保持し、`solidedge_set_concept_pose`に渡します。

```json
{
  "expectedDocument": "C:\\CAD\\ConceptMill5\\concept.asm",
  "manifestPath": "C:\\CAD\\ConceptMill5\\mechcue-concept.json",
  "valuesJson": "{\"X\":100,\"Y\":50,\"Z\":30,\"A\":45,\"C\":90}"
}
```

指令は増分ではなく絶対値です。毎回すべての軸を指定します。直線軸はmm、回転軸は度です。ゼロが基準状態で、直線軸の範囲は指定ストロークの±半分、Aは±110度、Cは±360度です。表示用のホーム値は現在の軸値の測定結果ではありません。現在の部品配置は取得結果の`actualMatrix`（メートル・列優先の4×4）で確認できます。

部品名と参照ファイルの一致で対象を確認します。機構定義はアセンブリと同じフォルダーの`mechcue-concept.json`に保存されます。部品・ASM・JSONを一緒に移動してください。部品名を変更、参照を置換した場合は一致しない操作を拒否します。

軸位置の変更はアセンブリを自動保存しません。保存するなら`solidedge_save_document`を明示実行します。範囲・対象不一致は移動前に拒否し、ソルバーが移動を拒否した場合は直前の配置への復元を試みます。復元に失敗した部品名はエラーに出します。

## 対応範囲と次の段階

今回のモデルは外形・軸連動・姿勢・ストロークの構想検討用です。モーター、ねじ、案内面、カバー、グリッパ開閉等の詳細はありません。軸値は工具先端のワーク座標ではなく各機械軸の値です。工具補正、TCP、逆運動学、NC/Gコード、切削・剛性計算、動的な連続衝突検出は未対応です。

生成部品は固定で配置し、親子連動はこのMCP機能の順運動学で計算します。CAD拘束を使った機構ソルバーとは別の方式です。生成部品に固定以外の有効なCAD拘束が追加された場合は、他の部品への波及を避けるため移動前に操作を拒否します。この制限は今回の概略軸MCPに限り、既存の部品座標駆動の仕様は変えません。

**生成モデルとMechCueタイムチャートの自動割り当ては今回未対応です。** 既存のタイムチャート操作MCPと概略モデル操作MCPはそれぞれ利用できますが、5軸の親子連動をチャートから一括駆動するには、概略軸を駆動先として扱う追加の接続処理が必要です。次の段階として、概略軸の自動登録→チャートによる連動→干渉対象の選択→PLC/NCデータとの対応を進める構成を想定します。

## 検証

通常の`--self-test`で4構成の親子移動、回転中心、傾斜後の子軸回転、範囲外・欠落軸・循環参照の拒否を確認します。ネイティブ検証はSolid Edgeを起動して、新規の検証先を指定します。

```powershell
MechCue.exe --concept-integration-test C:\CAD\FreshConceptTest
```

ローカル開発用検証はSolid Edge 2026のISO Metricテンプレートを使用します。新規のテスト文書だけを作成・閉じ、元の文書を再度アクティブにします。結果は検証先の`result.txt`に保存されます。
