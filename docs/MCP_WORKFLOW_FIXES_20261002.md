# 搬送機械の実機検討からのMCP修正（2026-10-02）

実機検討記録: `output/Gantry-MCP-study-20261002-1900/設計検討・MCP不足機能.md`。
本変更では、検討時にAPIへ迂回した操作とSolid Edgeライフサイクルを優先した。全ての不足機能を解消した状態ではない。バージョン変更、インストール、GitHub公開は行っていない。

## 実装した入口

MCPツールは70から85へ増加。

| ツール | 対応内容・制限 |
|---|---|
| `solidedge_get_application_state` | 状態、対象プロセスID、全開文書とDirty。プロセスだけで起動完了と判定しない。ライセンス待ちの確定診断は未対応 |
| `solidedge_start_application` | 登録済み実行ファイルから起動。既存インスタンス再利用。起動途中の重複起動を防ぐ。状態をポーリングする |
| `solidedge_exit_application` | 指定プロセスIDの一致と全文書の未保存状態を検査し、正常終了を要求。強制終了・編集破棄・自動保存なし |
| `solidedge_open_mechcue` | アドインの公開COMインターフェースでチャートを開く・接続しsessionIdを取得。更新したアドインのインストールが必要 |
| `mechcue_get_session_health` | Pipeを実際に照会し、UI準備状態とプロトコル版を返す。古いセッションファイルと生きた接続を区別する |
| `mechcue_start_operation` / `mechcue_get_operation` | 保存・移行・区間干渉確認の非同期完了照会。UUIDによる同一要求の二重実行防止。セッション内128件まで保持 |
| `mechcue_set_keyframes` / `mechcue_delete_keyframe` | 複数軸の一括置換、時刻指定削除。一括検証と1回のUndo |
| `solidedge_position_nested_part` | 親文書ごとのネイティブ参照キーで入れ子部品を特定。ローカル姿勢の変更、結果検証、失敗時復元 |
| `mechcue_bind_nested_part` | 概略XYZ軸と併用する追加の爪開閉等の駆動。既存の未割当トラックを使う。基準姿勢・参照キーの保存と復元 |
| `solidedge_set_variables` | 既存寸法／変数の名前指定一括変更。mm/degree変換、値の確認、失敗時の値復元 |
| `solidedge_get_custom_properties` / `solidedge_set_custom_property` | 設計条件や検討状態などのCustom属性の読取・文字列設定 |
| `solidedge_get_bom` | 入れ子構造を辿ったファイル単位の数量とキー。不完全な木は明示。製造BOM・材質・質量は未対応 |

## 修正した既存処理

- CAD保存に10秒を超えても、通信側が処理途中で打ち切らない。読込期限とCAD処理の寿命を分離した。従来の同期保存待ちは120秒へ延長した。
- UIがCAD保存で待っていても、別Pipe接続で健康状態・非同期処理結果を読める。
- MechCue側の例外理由をMCPへ渡し、汎用エラーで原因が失われる問題を改善した。
- AI保存失敗時に確認ダイアログを出して自動処理が停止する問題を改善した。
- 入れ子参照キーは親文書ごとに解決する。同一のキー値が別文書に存在しても混同しない。
- 入れ子駆動を含む設定はversion 3で保存する。旧版が子部品のキーを親アセンブリのキーとして誤解釈して駆動しないよう、旧版では読込拒否となる。
- 動画／区間確認後に、入れ子駆動を含む姿勢と概略駆動の内部状態を復元・検証する。
- 読込済みの子文書を開くときはDocuments.Openを繰り返さず、既存文書を再利用する。今回実機で再Openが停止したため追加した修正で、修正後の同操作の実機再検証は未完了。
- gantryテンプレート説明の軸階層を実装に合わせてY→X→Zへ訂正した。

## 使用手順

1. 作成・編集モードで起動を要求し、状態が`ready`または`ready_no_document`になるまで照会。
2. アセンブリを開き、`solidedge_open_mechcue(expectedDocument)`で明示的なsessionIdを取得。
3. 保存は`mechcue_start_operation(operation="save_document", argumentsJson={"expectedDocument":"絶対パス"}, requestId="新規UUID", sessionId)`を使う。
4. `mechcue_get_operation`で`completed`を確認する。タイムアウト後の再要求は同じUUID・同じ引数を使用する。`failed`のerrorは実際の理由。別セッションでは処理番号を引き継げない。
5. 区間確認はoperation=`check_motion`、引数`{"startTime":0,"endTime":16,"step":0.5}`。最大501姿勢、明示的にCADを動かして検査し、開始前の姿勢に戻す。離散点の結果で、連続衝突や最小隙間を保証しない。
6. 終了は全文書を利用者の意図に従って保存したあと、状態から得た正確なprocessIdで要求。終了要求と実際のプロセス消滅は別なので、状態を再確認する。

入れ子部品の姿勢変更・駆動は子アセンブリ文書を変更する。同じファイルの全参照に影響するため`modifySharedSubassembly=true`が必須。フレキシブルアセンブリ固有のインスタンス姿勢変更は未対応。子文書の形状・配置変更はその子文書も明示的に保存する。rootのMechCue設定保存だけで子文書まで保存されたとは扱わない。

## 検証結果

- アプリ／MCP／アドインのReleaseビルド: エラー・警告なし。
- 自己テスト: 11秒を要する保存の完了応答、並行健康照会、UUID二重実行防止、失敗結果保持、入れ子の保存・復元、一括編集の不正入力拒否・Undo。
- `scripts/Test-Mcp.py`: 85ツール公開、権限制御、新規セッション準備、一括編集・削除・Undo、非同期保存の再要求と具体的エラー保持、既存の動作パターン等。
- COM契約検査: 既存IUnknownのGUID・メソッド順・ベンダーDLL非依存、リボンリソース。
- Solid Edge 2026実機: 既存プロセス再利用、プロセスID不一致の終了拒否、未保存文書がある終了拒否、押出寸法10→12mm、Custom属性、参照キーによる子部品X=-50→-60mm、同一部品2個のBOM集計。記録は`output/Workflow-fixes-native-20261002-2/results.json`。
- 上記実機テストは最後の子文書再Openで停止した。確認済み操作までを実機検証済みとし、テスト全体の成功とは扱わない。新規テストファイルのみ作成した。元の画面への復帰・子文書保存完了は未確認。
- Solid Edge新規起動／正常終了、更新アドインのOpenChart、入れ子駆動を含む実機再生・保存再読込、区間確認は現行インストールへの反映後の実機検証が必要。既存ユーザーCADの終了や更新インストールをテストのために実行していない。

## 残る不足機能

| 優先度 | 未対応 | 今回対応との境界 |
|---|---|---|
| P0 | 概略単一部品群→適切なサブアセンブリ構造の自動生成、manifestと駆動先の一括再対応 | 設定移行は既存機能。今回は入れ子の特定・追加駆動まで |
| P0 | 把持・解放イベントとワーク追従の統合 | 爪開閉トラックは定義可能。把持対象の切替・追従は未実装 |
| P1 | 台形／S字補間と速度・加速度の設計評価 | 一括キー編集まで。既存補間は直線 |
| P1 | 干渉ペア除外、最小隙間、連続／掃引干渉 | 離散姿勢のネイティブ干渉確認まで |
| P1 | 穴の専用フィーチャ、面取り・フィレット・パターン | 押出・切削と既存寸法変更まで |
| P1 | 材質、質量・慣性、製造部品表 | 配置数量とCustom属性まで |
| P1 | 面／円筒を使う拘束、拘束一覧・自由度、標準購入品 | 既存の基準平面拘束まで |
| P1 | 穴注記、公差、断面・詳細図を備えた製造図面 | 既存の参照図・関連寸法まで |
| P2 | 起動・ライセンス待ち・モーダル待ちの詳細診断、CAD側全操作のジョブ化 | MechCue保存等のジョブ化と健康照会まで。CAD STAが待った場合の強制中断はしない |
| P2 | 全MCPエラーの統一コード、全クライアントのパラメータ名移行 | 原因メッセージは改善。既存ツールの公開引数名を破壊的変更していない |

API単位の保存・編集処理を追加した段階であり、把持搬送サイクルから製造図面までの完全な自動詳細設計が完了したとは扱わない。
