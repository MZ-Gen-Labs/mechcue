# 概念検討用チャートと検査結果の軽量化（2026-10-03）

本書は先行段階の記録。ここに記載したソフト側の残課題とテスト失敗への対応は、その後の `MOTION_INSPECTION_COMPLETION_20261003.md` を参照。

## 完了した変更

概念検討用の5軸モデルについて、各軸のチャートを主に1秒刻みに整理した。最大・最小、反転、停止区間の境界を保持し、各パターンの動作時間は変更していない。細かな表示点とCADでの検査点を同じ密度にする必要はないため、検査側も粗い点から開始する方式に変更した。

| 動作パターン | 各軸の変更前の点数 | 変更後 | 動作時間 |
| --- | ---: | ---: | ---: |
| 01 搬入・搬出位置への移動 | 97 | 25 | 24秒 |
| 02 割出し・接近・退避 | 129 | 33 | 32秒 |
| 03 五軸同時動作の検討 | 121 | 31 | 30秒 |
| 04 安全退避・基準復帰 | 73 | 19 | 18秒 |
| 05 全可動範囲・干渉探索 | 265 | 67 | 66秒 |
| 合計 | 685 | 175 | — |

通常の点検査は粗い点を使い、連続区間確認では移動量と部品外形から安全を確認できない区間を追加分割する。区間内の全キーは移動量の評価に利用するため、端点が同じ位置に戻る往復や360度回転も考慮する。従来の細かな検査点を選ぶ設定も残した。点検査の完了と連続経路の確認完了は別々に記録する。

各姿勢の結果には異常のある部品対と集計を保持し、正常な全組合せの繰り返しを除いた。部品識別情報は報告ごとに一度記録する。干渉、干渉の可能性、すきま不足を区別し、部品名を表示する。

検査中の部品対情報は100万件、コンパクトな姿勢結果は16 MiB、UI履歴は500件・32 MiBを上限とする。予算不足や未確認区間は安全と判定しない。履歴のファイル出力はストリームを使う。

MCPの検査操作結果は要約とreportIdを返す。`get_inspection_reports`は既定で要約を返し、詳細はreportIdを指定してページ取得する。1ページは最大100姿勢、応答は4 MiBまでで、継続位置を返す。以前の詳細結果を前提とするクライアントは取得方法を更新する必要がある。

## 検証結果

44部品・5パターンを変更後のローカルビルドで検査した。各検査で姿勢が復元され、すべての計画検査点で解析が完了した。既知の干渉5組と、判断が必要なすきま不足4組を引き続き検出した。全経路を安全とする結果ではない。

全可動範囲の旧結果は269,022,550バイト（265姿勢）、変更後は219,907バイト（67姿勢）だった。チャート整理と結果形式変更の両方を含む比較である。5パターンの結果合計は653,513バイト。証跡は `output/mill5-compact-inspection-20261003-01/` に保存した。

ローカルのMechCue本体・MCPのReleaseビルド、スモークテスト、Solid Edge実機の拡張運動検査19項目、MCP回帰検査23項目（102ツールの登録確認を含む）が成功した。密なキー、途中の衝突、反転、360度回転、同時多軸駆動、予算不足、取り消し、接触設定、姿勢復元、UI報告とページ取得を検証した。

全体セルフテストは既存のウィンドウ配置テストで失敗した。変更前のalpha.04配布物でも同じ失敗を再現したため、今回追加した処理に固有の失敗ではない。全体セルフテスト成功とは扱っていない。

履歴の容量説明文を修正した最終ビルドも成功した。ただし、ユーザーのMechCue画面を開き直した後のスモーク再検査は、既存のUndo/Redoショートカット登録テストで停止した。変更した検査処理に到達する前の失敗で、今回の再検査を成功とは扱わない。先行するスモークと実機UI検査は成功している。複数画面でのショートカット登録は別途確認が必要。
