# alpha.04 実5軸モデル検証結果

2026-10-03。インストール済み 0.3.1-alpha.04（70a6cc6）、Solid Edge 2026。

## 結論

5動作パターンの全範囲について、全キー時刻を含む検査点の解析を完了した。全パターンで異常があり、連続経路の無干渉・すきま保証は成立しない。CAD形状や動作グラフを安全な設計に修正した作業ではない。

## 対象と条件

対象は `output/Mill5-detail-study-20261003-1007/detail/mill5-detail.asm`。6剛体サブアセンブリ、末端部品44点、アセンブリ込み50ノード。全946組から、固定取付・案内・代表軸接続の接触41組を理由付きで対象外とし、905組を検査した。判断と配置キーは `output/mill5-alpha04-inspection/contact-review.json` に保存。

要求すきま0.5 mmは調査用の仮値であり、製造・使用仕様として決定した値ではない。数値余裕0.01 mm、内部部品検査・連続確認を有効にした。

## 全パターンの結果

1秒刻みに全キー時刻を追加した。グラフのキーは0.25秒間隔なので、実検査点も0.25秒間隔。異常があっても終点まで検査した。

| 動作 | 全範囲 [s] | 実行点 / 予定点 | 異常の組数 |
|---|---:|---:|---:|
| 01 搬入・搬出位置への移動 | 0–24 | 97 / 97 | 7 |
| 02 割出し・接近・退避 | 0–32 | 129 / 129 | 6 |
| 03 五軸同時動作の検討 | 0–30 | 121 / 121 | 6 |
| 04 安全退避・基準復帰 | 0–18 | 73 / 73 | 6 |
| 05 全可動範囲・干渉探索 | 0–66 | 265 / 265 | 9 |

全記録で `samplingComplete=true`、`analysisComplete=true`、`poseRestored=true`、`allSamplesClear=false`、`continuousPathCertified=false` を確認。全検査点を実行したという意味であり、検査点間まで安全を保証したという意味ではない。異常がある経路は連続すきまの証明を停止して区間状態を記録する。

### 実干渉5組

要求すきまゼロのSolid Edge専用干渉判定でも確認した。

| 部品の組 | 確認した姿勢 |
|---|---|
| 固定構造ベース ↔ Y送りモーター | 基準姿勢から常時。既知の設計干渉 |
| 固定構造コラム ↔ Y送り後側支持部 | 基準姿勢から常時。既知の設計干渉 |
| YFeedのX送りモーター ↔ XFeedのテーブル | 動作01の18秒: X=+220, Y=-120, Z=150 mm。動作05の10秒: X=+300, Y=0, Z=150 mm |
| YFeedのX送りモーター ↔ XFeedのA軸支持部2 | 動作05の10秒: X=+300 mm |
| 工具 ↔ ワーク | 動作05の35秒: Z=-200 mm、X=Y=A=C=0 |

A/Cは度。工具とワークの重なりを許容する加工区間・除去形状は未定義のため、意図した接触として自動除外しない。

すきま0.5 mmの検査では、追加異常は動作01の15.25–20.75秒、動作05の8.25–12.5秒（モーターとテーブル）、9–11.25秒（モーターとA支持部）、33.75–36.25秒（工具とワーク）に出た。これは異常が出た検査点の最初・最後であり、連続した干渉の厳密な開始・終了時刻ではない。

### 未確定のすきま不足4組

ベース↔Yサドル、Y送りねじ↔Yサドル、Yサドル↔Xテーブル、X送りねじ↔Xテーブル。専用最小距離は0 mmで、要求0.5 mmを満たさない。基準姿勢の要求すきまゼロの判定では実干渉として検出されなかった。代表形状の接触なのか、逃げを設計すべき箇所なのか未確定のため、対象外にしていない。

## MechCue MCP / UI の残課題

### 1. 結果の生成・保持・取得の軽量化（優先度高）

各姿勢の `analysis.pairs` と `leafPairs` に全末端組を重複保持し、長い配置キーも毎回繰り返す。100点程度でもMCP応答記録が100 MB規模になる。

UIの動作04の詳細検査では `Cannot allocate a buffer of size 2147487687.` が出て解析未完了となった。検査中のSolid Edge作業セットは約11 GBまで増加した。確認できた原因は結果バッファの確保失敗であり、Solid Edgeの再起動やメモリ漏れと断定しない。

動作05の265点の処理は完了したが、`mechcue_get_operation` はJSON-RPCエラー `-32603: An error occurred.` を返した。同じMechCueのローカルAPIを読み取り専用で直接取得すると、269,022,550 byteの応答を正常取得できた。MCP経由の大きな結果取得の失敗として再現。転送上限・シリアライズ制約などの正確な原因は追加の切り分けが必要。

必要機能: 配置表の共通化、全ペア配列の重複削除、通常記録は要約・異常のみ、区間/記録/ページ単位の詳細取得、ファイルへの逐次出力、履歴のバイト上限。`get_operation` の軽い状態・要約と詳細取得を分離する。結果生成・保存中の中止と部分結果の保持も必要。

### 2. 点数の事前見積もりと区間検査

UI既定（表面移動目安5 mm、最大5001点）では動作02/03/05が `Sampling budget exceeded; shorten the inspection interval or explicitly adjust limits. No CAD motion performed.` となった。動作01は363点で全範囲完了。動作04は上記バッファ確保失敗。

必要機能: 点数・記録量を先に見積もり、区間を分けて実行し、全範囲の実行状況を示す。回転の表面移動量の計画には駆動対象の外形・回転中心を使い、モデル全体の保守的な半径による過剰細分化を減らす。予算超過を安全と判定しない挙動は維持する。

### 3. UIの異常部品名・分類の表示

対象外キーと最小距離の組が大量に表示され、異常箇所を探しにくい。内部検査の `analysis.pairs` は `Part1/Part2` 形式だが、詳細欄の組名表示は旧形式の `first.name/second.name` を参照しており、異常の全組名が表示されない。

必要機能: 異常だけの表、部品名、姿勢・時刻、専用干渉と最小距離不足の区別、未確認理由、CAD内の配置選択。APIでも干渉状態とすきま不足を別フィールドで保持する。

### 4. このCodexセッションのMCP接続

設定済みコネクターは `Transport closed` で、公開ツール一覧も旧版の状態だった。インストール済みalpha.04のMCPプロセスを直接起動するJSON-RPC経由で検査した。MechCueの機能不備と接続側の状態を混同しない。最新ツールの利用にはコネクターの再接続も必要。
